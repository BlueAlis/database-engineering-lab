# Curriculum

A rough syllabus, not a fixed order — topics will overlap and loop back
(e.g. concurrency problems will resurface once JPA/Hibernate is in play).
Difficulty starts at junior/mid backend level and increases gradually. Each
topic file lists what "done" roughly covers; it is not a checklist to rush
through.

1. [SQL](01-sql.md)
2. [Database Design](02-database-design.md)
3. [Indexing](03-indexing.md)
4. [Query Optimization](04-query-optimization.md)
5. [Transactions](05-transactions.md)
6. [Concurrency](06-concurrency.md)
7. [JPA/Hibernate](07-jpa-hibernate.md)
8. [Database Internals](08-database-internals.md)

Corresponding hands-on work lives in [`../labs/`](../labs/), one folder per
topic. A topic isn't "complete" because the curriculum file has been read —
it's complete when there's a lab, a real experiment, and a reflection behind
it in `progress.md`.
