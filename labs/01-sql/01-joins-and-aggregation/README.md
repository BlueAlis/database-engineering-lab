# Lab 01-sql / 01-joins-and-aggregation

## Why this lab

Stated starting point: comfortable with simple single-table SQL, but joins
and aggregation so far have mostly been generated by JPA/Hibernate rather
than hand-written. This lab is entirely about closing that gap — no ORM,
just SQL against a real Postgres instance.

## Learning Objectives

- Write correct `INNER JOIN` vs `LEFT JOIN` queries and know which one
  actually preserves unmatched rows through to the result.
- Place a filter in `ON` vs `WHERE` correctly on an outer join — get the
  right answer for the right structural reason, not by accident.
- `GROUP BY` at the correct grain, and use `COUNT(DISTINCT ...)` only on a
  column actually guaranteed unique (not just "probably unique").
- Keep rows with zero matches (e.g. a customer with no completed orders)
  in an aggregate's output instead of silently dropping them.
- (Stretch) Use a window function (`RANK()`/`PARTITION BY`) to pick a
  per-group result, and partition by the right dimension for the question
  actually being asked.

## Scenario

A small synthetic construction-material store: customers, products, orders,
and order line items. See [setup/schema.sql](setup/schema.sql) for the exact
structure — read the DDL yourself before starting rather than waiting for a
description of it.
